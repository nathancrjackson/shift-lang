# The Shift Project

**Please note that this project is in its early development stage and breaking changes may occur**

## The Mission

Shift is a domain-specific language (DSL) designed for writing clear, portable, and reliable data logic. It bridges the gap between data files (like JSON/YAML) and full-scale programming languages (like C or Go). It is intended to be a modern alternative to embeddable languages like Lua.

Its primary goal is Readability and Simplicity. It deliberately avoids complex programming concepts (like pointers, memory management, or function overloading) to ensure that scripts are easy to write, easy to audit, and easy to transpile into other formats.

## Core Design Philosophy

1.	**Simplicity First:** The language prioritizes ease of understanding over raw execution speed. It favors a readable left-to-right data flow and removes hidden behavior; there is only one way to do things (e.g., no function overloading, consistent bracket notation for data access).

2.	**Portable Architecture:** Scripts are not just executed; they are parsed into a JSON Abstract Syntax Tree (AST). This allows the logic to be:
- Stored and analyzed as data.
- Executed by a lightweight interpreter.
- (Future) Transpiled into C for creating standalone, portable binaries.

3.	**Type-Safe but Flexible:** It uses a hybrid type system. Variables are strongly typed (`string`, `number`, `bool`) to prevent bugs, but collections (`map<any>`, `list<any>`) allow for flexible data processing (like handling JSON payloads).

## Key Features

### 1. Readable Pipeline Processing
To avoid nested function calls that are hard to read, Shift Script supports a Pipe Operator (|) with explicit placement. This allows data transformations to read like a story from left to right.
- Unreadable Way: `ansitransform_toupper(trim_string(name))`
- The Shift Way: `name | trim_string($pipe_value) | ansitransform_toupper($pipe_value)`

### 2. Zero-Value Safety

Shift Script eliminates "undefined variable" errors. By default, variables are strictly scoped and automatically initialized to safe defaults upon declaration.
- `string s;` automatically becomes `""`.
- `number n;` automatically becomes `0`.
- `bool b;` automatically becomes `false`.
- `list<T> l;` automatically becomes `[]`.
- `map<T> m;` automatically becomes `[]`.

The one exception to this is `nullable<T>`, which is initialized as `null`.

### 3. Robust Collections

The language treats data structures as first-class citizens. It supports generic Lists and Maps with literal syntax, making it easy to define complex data trees inline.
```
map<any> user = [
    "name": "Ringo",
    "age": 42,
    "roles": ["admin", "editor"]
];
```

### 4. "Magic" Context Variables

The runtime exposes context-aware variables prefixed with $ to simplify logic without cluttering function signatures. These cannot be set by user code.
- `$pipe_value`: The current value in a pipeline.
- `$thrown_message`: The specific error details inside a catch block.
- `$line_num`: The current source line number (useful for debugging).

## Architecture: How It Works

The language operates on a three-stage pipeline:
1.	**Shift Script (.shift):** The human-readable source code.
2.	**Shift Tree (.stree):** The intermediate JSON AST generated by the compiler. This serves as the portable "source of truth" for the logic.
3.	**Shift Engine:** An interpreter that directly executes the Shift Tree (JSON AST) for dynamic workflows.

### Example Script
```
struct User [
    string $name, // 1. The prefix $ indicates fields that are both required and immutable
    string role,
    number login_count
]

function main() number {
    
    // 2. Define data structures (Map Literal)
    User our_user = [
        "$name": "alice",
        "role": "  admin  ",
        "login_count": 42
    ];

    // 3. Logic using "Pipes" for clean transformation
    // "$pipe_value" explicitly shows where the data goes
    our_user["role"] = our_user["role"] 
        | trim_string($pipe_value) 
        | ansitransform_toupper($pipe_value);

    // 4. Output
    string msg = "User " & our_user["$name"] & " is ready.";
    print_line(msg);

    // 5. Error Handling with Magic Variables
    try {
        if (our_user["login_count"] < 0) {
            throw error "Invalid login count";
        }
    } catch {
        print_line("Audit failed: " + $thrown_message);
        return 1;
    }

    return 0;
}
```

## Language Reference

### Types & Variables
- **Primitive Types:** `number`, `string`, `bool`, `null`, `any`.
- **Initialization:** Zero-value defaults applied automatically (`""`, `0`, `false`, `[]`).
- **Assignment:** Strict type checking based on declaration.
- **Scope Isolation:** Strict no-redeclaration (even in nested blocks) and local variables cannot shadow outer variables.

### Collections
- **Lists:**
  - Literals: `[1, 2, 3]`
  - Generics: `list<number>` (Enforced type safety).
  - Recursive Generics: `list<list<number>>` supported.
- **Maps:**
  - Literals: `["key": "value"]`
  - Generics: `map<string>`. Keys are strictly strings.
- **Structs:**
  - Definitions: `struct Account [ string uid ]`.
  - Behavior: Treated as strict maps with enforced keys and types.
  - Modifiers: Keys prefixed with `$` (e.g., `string $uid`) are Required during initialization and Immutable thereafter.
- **Access:** Standard index syntax `arr[0]` and `map["key"]`. Supports deep access inference (e.g., `matrix[0][1]`).
- **Modification:** Use `delete collection[index]` or `delete map["key"]` to remove items.

### Nullables
- `nullable<T>` allows a variable to hold a specific type or `null`.
- **Access Rules:** Accessing index items in `nullable<list<number>>` pierces the list/map wrapper but maintains nullability on the result.

### Functions
- **Definition:** `function name(type arg) return_type { ... }`
- **Scope:** Global registration; parameters and body variables are locally scoped.
- **Argument Passing:** Strictly Pass-by-Value. All data, including Collections (`list`, `map`) and Structs, is copied when passed to functions. Modifications inside a function do not affect the caller's data.
- **Return:** Explicit return types required. `void` is rejected in favor of `none` (conceptually similar to null return).
- **Hoisting:** Functions can be called before they are defined in the file.

### Control Flow
- **Conditionals:** `if`, `else if`, `else`. Braces `{ ... }` are required even for single lines.
- **Loops:**
  - `while (condition)`
  - `for (item in collection)`
  - `for (i in 0 to 10)`
  - Keywords: `break` (exit loop) and `skip` (continue to next iteration).
- **Error Handling:**
  - `try { ... } catch { ... } review { ... }`
  - `catch`: Handles technical/runtime errors. Triggered by system faults or `throw error`.
  - `review`: Handles business logic soft failures. Triggered strictly by `throw alert`.
  - Critical: `throw critical` exits the script immediately with a non-zero code.

### Operators
- **Pipeline:** `|` with strict Left-to-Right evaluation into `$pipe_value`.
- **Math:** `+`, `-`, `*`, `/`, `%`.
- **Logic:** `and`, `or`, `xor`, `not`.
- **Comparison:** `>`, `<`, `>=`, `<=`, `==`, `!=`.
- **Concatenation:** `&` (e.g., `"Hello " & "World"`). Specifically for joining strings. Other types are automatically cast to string when using this operator.
- **Casting:** `value as type` (e.g `10 as string`).
- **Containment:** `map has "key"` (Returns bool).
- **Search:** `string search "/regex/flags"` (Returns `list<RegexResult>`).
- **Introspection:**
  - `size of value`: Returns length/size of collection or string.
  - `type of value`: Returns string representation of type.
  - `inspect value`: Returns `InspectionResult` (Map with `$type`, `$size`).
- **Byte Manipulation:**
  - `pack list<number>`: Converts list of numbers to string.
  - `unpack string`: Converts string to list of character number codes.

### Design Decisions
- **Comments:** `#` is rejected. Strictly `//` and `/*` `*/`.
- **Assignments:** Chained assignment (`x = y = 5;`) is rejected.
- **Syntax:** Single-line control flow without braces is rejected (e.g., `if (x) return;`).
- **Keywords:** `void` is rejected; use `none` or a specific return type.
- **Logic:** C-Style symbols (`&&`, `||`) are rejected in favor of readable words (`and`, `or`).
- **Uninitialized Variables:** Rejected. Solved via Zero-Value/Nullable strategy.
